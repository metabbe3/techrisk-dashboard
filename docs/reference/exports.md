# Export Architecture (2026-09-29 redesign)

Detailed reference for every export preset. CLAUDE.md carries only the pointer — this file is the source.

The incident Export button offers 5 presets via `App\Filament\Actions\ExportActionSchema` (form schema + `applyFilters()` + `columnOptions()` — single source for every preset):

1. **Executive Report** (`Exports\ExecutiveIncidentsExport` + `Sheets\ExecutiveDataSheet|ExecutiveCalcSheet|ExecutiveSummarySheet|ExecutiveQuarterSheet`) — KPI cards + 4 native Excel charts (monthly incidents, severity mix, MTTR trend, potential-vs-recovered). KPIs/charts are **widget-aligned** (owner rule 2026-09-30, same rules as the Group-By Summary): counts/potential/actual keep only non-excluded fund statuses, Potential = open cases, Actual = Completed, Recovered = eligible sum — `ExecutiveCalcSheet::computeKpi()` is the single KPI implementation. Per-quarter tabs (`ExecutiveQuarterSheet`, one per quarter with rows, between Summary and Data) scope the same KPIs to that quarter plus a severity row (P1–P4 counts + one combined X1–X4). Charts live on the Calc sheet with their source data. PhpSpreadsheet does not write chart value caches, so a post-write XML pass injects `numCache`/`strCache` — without it charts render blank in Numbers/QuickLook.
2. **Quarterly Report** (`Exports\QuarterlyReportExport` + `Sheets\QuarterlyCaseSheet`, owner decision 2026-10-05) — the owner's hand-made quarterly report as a live export. **No Summary sheet** (owner 2026-10-05, iteration 2). 4 case tabs with the **All Tabs membership rules** (classification Incident; Recovered = `recovered_fund > 0`; Fund Loss = Confirmed loss; Non Fund Loss = Non fundLoss) and 12 fixed columns: ID, Title, MTBF (days), Severity, Incident Status, Quarter (`Qn YYYY`), Incident Date, Actual Fund Loss (Rp), Fund Status, Domain (= `business_category` — no domain column exists), Root Cause Category, Responsible Team; tab footer = case count + Avg MTBF as mean of the displayed column, then the 2 severity/stats banner rows (`WritesSeverityFooter`, owner rule 2026-10-27). After the case tabs, one tab per quarter (`Qn YYYY`, derived from `incident_date`, filtered `whereBetween` via `QuarterRange` — never `where('quarter')`) holding only that quarter's incidents, Incident classification only; quarters with no rows get no tab. **Scope is always the full filtered set** — the quarter tabs are the breakdown. MTBF column uses the **full-year gap sequence** (`Exports\Concerns\ComputesMtbfSequence`, shared with `IncidentTableExport`), NOT the per-tab sequence of All Tabs sheets — same number can differ between presets by design.
3. **Group By** (`Exports\GroupedIncidentsExport` + `Sheets\GroupSummarySheet|PerCategorySheet`) — one sheet per value of a chosen dimension (business_category / root_cause / responsible_team / pic / severity / incident_type / quarter). `quarter` has no backing column: values are derived in PHP from `incident_date` as `YYYY-Qn` (label `Qn YYYY`), and `PerCategorySheet` filters it with a `whereBetween` date range — never `where('quarter', ...)` (silent no-op). Front Summary sheet carries per-group Cases, Avg MTTR (min + days), **Avg MTBF (days)**, fund totals — **widget-aligned** (owner rule 2026-09-30): Cases excludes fund statuses in `FundStatus::EXCLUDED_FROM_COUNTS`, Actual Loss = Completed only, Potential = open cases only, Recovered = severity-eligible sum; rows dropped by those rules get their own `Excluded - <FundStatus>` tabs instead of vanishing. Multi-category incidents appear in every matching sheet (by design).
4. **All Tabs** (`MultiSheetIncidentsExport`) — 14 sheets mirroring the table tabs (the "Non Incident" sheet is gone: exports are METRIC_ELIGIBLE-only, so it would be structurally empty; the table's own tab stays).
5. **Custom** — pick columns (`ExportActionSchema::columnOptions()`) + XLSX/CSV.
6. **Markdown ZIP** (`export_markdown_zip` action on `ListIncidents`, grouped since 2026-11-10 with the preset form's `export` action inside ONE header `ActionGroup` labeled "Export" — the detail page's group shape; members relabeled "Excel Report" / "Markdown ZIP") — one folder per incident: full `IncidentMarkdownExporter::generate()` md + every investigation document as md (cached-first via `getMarkdownContent()`, else `DocumentConverterService::convert()`; skipped docs noted in a `## Document conversion notes` appendix), plus a root `index.md`. Built by `Services/Markdown/IncidentMarkdownZipService` over `getFilteredTableQuery()` + `ExportActionSchema::baseExportScope()` (the METRIC_ELIGIBLE single source — `applyFilters()` calls it too). Inline build; temp zip on local disk, `deleteFileAfterSend`.

Optional export filters (severity / status / type / fund status / PIC / business category / root cause / **quarter** `f_quarter`, all multi-select) apply **on top of** the table's current filters via `ExportActionSchema::applyFilters()`. `applyFilters()` **permanently restricts severity to `METRIC_ELIGIBLE`** (owner rule 2026-09-30) — G / Non Incident never reach any preset; the 3 fresh-query Issue sheets in `MultiSheetIncidentsExport` carry the same `whereIn`.

**The `f_*` filters scope the MTBF math, not just the rows** (owner report 2026-10-23): every export sequence — `ComputesMtbfSequence` (Custom via `IncidentTableExport`'s `mtbfScope` ctor arg; Quarterly Report via `QuarterlyCaseSheet`'s 3rd ctor arg, always the **full filtered set**, never per-tab) and All-Tabs' per-tab `computeMtbfForIncident()` (based on the sheet's own filtered query) — runs over the filtered builder, so filtered-out rows telescope over. Footer "Avg MTBF" then equals scoped span/(n−1). The 3 Issues sheets keep always-all-issues rows AND sequence (their queries carry metric-membership clauses like `whereNotNull('mtbf')` — never reuse them as a sequence base).

**Widget-aligned baseline (owner rule 2026-10-23, amended 2026-10-27):** `ExportActionSchema::baselineQuery()` — the baseline set for general surfaces is **Confirmed loss + Non fundLoss + null/empty fund_status** (`widgetFundScope()` — delegates to `Incident::excludedFromCounts()`, the dashboard **total tile's** exact predicate, so the two surfaces cannot drift; original strict-`IN` version silently dropped such rows, prod 2026 showed widget 39 vs export 38), unless the user explicitly picks Fund Status values in the export form (explicit choice wins, and stays strict — null excluded). Applies to: All-Tabs' All Cases + Completed Cases sheets (`MultiSheetIncidentsExport` main query; 4th ctor arg = the all-statuses base for every other Incident sheet), Quarterly Report's All Cases + quarter tabs + every tab's MTBF sequence (2nd ctor arg = dedicated base for Recovered/Fund Loss/Non Fund Loss rows), Custom, and Executive's data/charts. NOT applied to: the dedicated fund-status tabs themselves, Recovered Cases / On Going / P4 / Non-Tech sheets, the 3 Issues sheets, Group By (already widget-aligned per-metric internally — owner rule 2026-09-30 — and its `Excluded - <FundStatus>` tabs need the full set), and the Markdown ZIP (a document archive, not a metric surface).

**Fund numbers in every export render as Rupiah via the native Excel number format** (`"Rp "#,##0`, defined once in `Exports\Concerns\IdrFormat`) — cells stay real summable numbers, never `'Rp x.xxx'` strings. Fixed-layout sheets use `WithColumnFormatting`; dynamic-column sheets (Custom/All Tabs) compute fund letters via `IdrFormat::letters()`. Quarter parsing (`"YYYY-Qn"` → date range / label) lives in `Exports\Concerns\QuarterRange`.

**Rule:** every export class = its own PSR-4 file. Shared query filtering goes in `ExportActionSchema`, shared stats in `Statistics/IncidentStatsFooterData` — never duplicated in handlers.

**Severity footer (owner rule 2026-10-27, restyled to banners same day):** every incident-listing tab of every preset ends with two single-line banners from `Exports\Concerns\WritesSeverityFooter::writeSeverityFooter($sheet, $row, $source)` (rows $row and $row+1), each **merged across the table's full width** — a per-column grid inherits the incident table's column widths and reads badly (owner, iteration 3). Banner 1: `P1: n | … | X4: n` (zeros shown, `Severity::METRIC_ELIGIBLE` order); banner 2: `Avg MTTR (mins): x | Avg MTTR (days): x | Avg MTBF (days): x | Fund Loss: n | Non Fund Loss: n` — Avg MTBF (owner 2026-10-30) is passed in by each call site as its OWN summary value (Quarterly footer row, All-Tabs per-sheet stats, Custom's displayed-column mean, Issues-MTBF's metric), so banner and summary cannot drift and each preset keeps its sequence semantics; stored-metric sheets without a sequence (`PerCategorySheet`, `ExecutiveDataSheet`) pass null and the segment is omitted (unit-labeled deliberately: the days bucket holds every day-granularity status — Confirmed loss, Potential recovery, Fully recovered, Non Tech Loss — so a "Fund Loss" label would contradict the Confirmed-loss-only count beside it) — Yellow-fill bold bordered centered cells matching the sheets' summary headers; `-` when a bucket is empty. Merged banner spans `max(table width, L)` — merged cells CLIP (no text overflow), so the min-L floor keeps the ~95-char stats line readable on narrow Custom sheets while wide sheets span their own table width. **Avg MTTR is split by the storage sign convention** (owner 2026-10-13): mttr ≥ 0 = minutes bucket, mttr < 0 = elapsed-days bucket averaged `abs()` — the two units are never averaged together. The counts describe **that tab's own rows** (a null-fund row counts in severity but lands in no fund bucket), so tab-vs-widget count differences read straight off the sheet. Sources: the tab's Builder (5 sheets) or its loaded Collection (`IncidentTableExport`, FromCollection) — both paths implement the identical sign split. Load-bearing detail: `reorder()` on every grouped/avg clone (MySQL `ONLY_FULL_GROUP_BY` error 1055 — SQLite tests can't see it). Zeros come from `?? 0` inside the banner strings — the old grid's `fromArray(..., strict=true)` gotcha died with the grid (loose compare drops zero cells; beware if a grid ever returns). Surfaces: Quarterly case + quarter tabs, All-Tabs' 12 `SingleIncidentSheetExport` sheets + `All Issues` + the 2 Issues metric sheets, Custom, Group-By `PerCategorySheet` (its first footer — `WithEvents` added), Executive `Data`. Skipped: Executive Summary/Calc/Quarter cards (calc surfaces; quarter tabs already show P1–P4 + combined X1–X4), `GroupSummarySheet`, Reporting/Analytics sheets.

## Export-related business rules

- EXPORTS (all 5 presets incl. the Issue sheets) exclude G / Non Incident rows entirely.
- `mttr_formatted` renders positive MTTR as plain minutes ("180", not "3h 0m") — negative stays "X day(s)", null "-" (owner rule 2026-09-30).
- Export per-row MTBF columns render `-` for the first incident of each year (no predecessor — the old Jan-1 `dayOfYear` anchor made the column mean ≠ span/(n−1)), and every export "Avg MTBF" summary is the **mean of the displayed column** (single-year sets: exactly the widgets' span/(n−1)) — owner report 2026-09-30 (14.11-vs-14.222 reconciliation); the Issues-MTBF sheet follows the same rule.
- Export MTBF sequence caches are **per-instance, never `static`** — a static cache froze the year's sequence inside long-lived FPM workers, so newly created incidents rendered `-` mid-year and vanished from column and bottom (prod bug 2026-09-30).
- **Export filters scope the sequences** (owner report 2026-10-23): a `f_fund_status = [Confirmed loss, Non fundLoss]` export reproduces the owner's hand-made 2026 sheet (~7,6) — gaps telescope over excluded rows instead of the unfiltered chain (~3,8). Unfiltered exports are unchanged.
- A tab with no positive (minutes) MTTR shows `-` as Avg MTTR, not 0.
- In stored-metric sheets (ExecutiveDataSheet, PerCategorySheet) a non-outlier's null stored mtbf renders **0**, not blank (owner 2026-10-01); sequence sheets keep `-` for first-of-year.
- Outlier rows keep their table/export row; their own MTTR/MTBF cells render the literal **`Outlier`**.
- All-Tabs sheets sequence MTBF **per-tab** (`SingleIncidentSheetExport::computeMtbfForIncident()`); Custom/Quarterly use the full-year `ComputesMtbfSequence` — two semantics, do not merge.
